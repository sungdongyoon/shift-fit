# Shiftfit

스케줄 근무 업장을 위한 월간 근무표 웹 애플리케이션입니다. 근무 타입을 만들고 날짜별로 직원을 배정하면서, 직원별 근무·휴무 현황을 한 화면에서 확인할 수 있습니다.

현재 버전은 **0.1.0 · MVP**입니다. 월간 캘린더를 중심으로 동작하며, 근무표는 편집 후 저장 버튼으로 Supabase DB에 반영합니다.

## 주요 기능

| 영역 | 기능 |
| --- | --- |
| 왼쪽 · 근무 타입 | 이름, 시작·종료 시간, 색상 등록 및 수정·삭제 |
| 중앙 · 월간 캘린더 | 월 이동, 오늘로 이동, 날짜별 일정 배정·수정 |
| 오른쪽 · 근무 설정 | 월 기준 휴무 횟수 설정, 직원별 횟수 확인 |
| 오른쪽 · 근무자 목록 | 이름·고유 색상 등록, 검색, 정보 수정, 개인 일정 강조 |

- **계정 인증**: 이메일·비밀번호 회원가입, 이메일 인증, 로그인·로그아웃, 비밀번호 재설정을 제공합니다. 로그인한 사용자만 근무표 화면에 접근합니다.
- **직원마다 하루 하나의 일정**: 근무·휴무·연차·기타·미배정 중 하나를 선택합니다. 근무 시작일은 필수이며, 해당 날짜부터 캘린더와 PDF에 표시됩니다. 시작일 이전은 휴무·미배정 집계에서 제외하며 이후 일정이 없는 날짜는 미배정으로 시작합니다. 휴무는 직접 선택해 저장하며, 미배정과 별도로 집계합니다.
- **월별 휴무 확인**: 기본 기준은 직원당 월 8회이며, 월별로 변경할 수 있습니다. 휴무 횟수가 기준과 다르면 빨간색과 굵은 글씨로 표시합니다. 연차와 기타는 휴무 횟수에 포함하지 않습니다.
- **읽기 쉬운 근무표**: 캘린더에는 직원 이름을 표시하고, 근무 타입의 색상으로 일정을 구분합니다. 근무는 시작 시간순으로, 같은 시간이면 이름순으로 정렬합니다. 근무 외 일정은 뒤에 표시합니다.
- **근무 타입 일괄 반영**: 근무 타입은 월별로 관리합니다. 이름·시간·색상을 수정하면 해당 월의 기존 배정에만 반영하고 다른 월은 변경하지 않습니다. 타입을 삭제하면 해당 월의 목록에서만 제거하며 기존 일정은 마지막 설정으로 유지됩니다. 종료 시간이 시작 시간보다 이르면 다음 날 종료로 표시합니다.
- **직원 삭제**: 근무자를 삭제하면 모든 월의 연결된 일정도 함께 삭제됩니다. 삭제 직후 알림의 실행 취소로 되돌릴 수 있습니다.
- **대한민국 공휴일**: 공휴일 날짜와 이름을 빨간색으로 표시합니다. 대체공휴일과 데이터에 반영된 임시공휴일·선거일도 표시합니다.
- **수동 저장과 실행 취소**: 편집 내용은 화면에만 적용하고, 상단 저장 버튼을 누르면 변경한 항목을 한 번에 DB에 반영합니다. 미저장·저장 중·실패 상태를 표시하며 월 이동과 로그아웃 전에는 저장 여부를 확인합니다. 마지막 편집은 실행 취소할 수 있습니다.
- **기타 메모**: 기타 일정에 간단한 메모를 저장하고 다시 편집할 수 있습니다. PDF에는 이름 옆에 표시하며, 긴 내용은 한 줄 말줄임으로 출력합니다.
- **PDF 다운로드**: 캘린더 상단 오른쪽에서 현재 월의 근무표를 PDF로 저장합니다. 근무·근무 외 일정을 합친 근무 타입 범례, 캘린더, 직원별 근무·휴무·연차·기타·미배정 횟수 순서로 출력합니다. 미배정 일정이 있으면 건수를 확인창으로 안내합니다. 확인하면 미배정을 포함한 PDF를 다운로드하고, 취소하면 다운로드를 중단합니다. 한글 글꼴을 포함하며 직원이 많으면 여러 페이지로 나눕니다.
- **반응형 화면**: 작은 화면에서는 패널을 세로로 배치하고 캘린더를 가로로 스크롤할 수 있습니다. 터치 환경에서는 일정 추가 버튼을 항상 표시합니다.

직원이 없는 초기 화면에서는 예시 근무표를 불러와 기능을 살펴볼 수 있습니다.

## 시작하기

Node.js 22 이상과 npm이 필요합니다. 개발 환경은 Node.js 24를 권장하며 의존성은 `package-lock.json`을 사용해 설치합니다. 인증에는 Supabase 환경 설정이 필요하며 공휴일 API 키는 필요하지 않습니다.

```bash
git clone https://github.com/sungdongyoon/shift-fit.git shiftfit
cd shiftfit
npm ci
cp .env.example .env.local
# .env.local에 Supabase 공개 연결 정보를 입력합니다.
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000)에 접속합니다. 포트가 이미 사용 중이면 터미널에 표시된 주소를 확인합니다.

배포용 빌드를 로컬에서 실행하려면 다음 명령어를 사용합니다.

```bash
npm run build
npm run start
```

### macOS 바탕화면에서 개발하기

macOS의 `Desktop` 아래에 있는 프로젝트는 `npm run dev` 실행 시 로컬 런타임을 자동으로 준비합니다. 이 환경에서는 별도 `npm ci` 실행 없이 `npm run dev`로 시작할 수 있습니다.

- 소스는 원래 프로젝트 위치에 유지합니다.
- `node_modules`와 `.next`는 `~/Library/Caches/shiftfit/<프로젝트 경로 해시>`에 심볼릭 링크로 연결합니다.
- 첫 실행 또는 `package.json`·`package-lock.json` 변경 시 캐시 경로에서 `npm ci`를 실행합니다.
- 준비가 끝나면 Next.js 개발 서버를 시작합니다.

의존성을 변경한 뒤에는 `npm run dev`를 실행해 캐시와 연결을 갱신한 다음 빌드합니다. 바탕화면 이외의 경로와 다른 운영체제에서는 일반적인 설치·실행 방식을 사용합니다. 이 스크립트가 소스 폴더의 iCloud 동기화 설정을 변경하지는 않습니다.

## 인증 설정

`.env.local`에 아래 값을 설정합니다. 실제 연결 정보는 Git에 커밋하지 않습니다.

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

- Supabase Authentication에서 이메일 가입과 이메일 인증을 활성화합니다.
- URL Configuration의 Site URL을 `http://localhost:3000`으로 설정합니다.
- Redirect URLs에 `http://localhost:3000/auth/callback`과 `http://localhost:3000/auth/callback?next=/update-password`를 추가합니다.
- 기본 메일 템플릿은 PKCE 콜백을 사용합니다. 별도로 TokenHash 템플릿을 사용하는 경우 가입 링크는 `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email`, 재설정 링크는 `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery`를 사용합니다.
- 배포할 때는 Site URL 환경 변수와 Supabase 허용 URL을 실제 HTTPS 도메인으로 변경합니다. 인증 페이지는 연결 설정 전에도 표시되며 폼 제출은 비활성화합니다.
- 일반 고객에게 이메일을 보내려면 Supabase의 기본 테스트 메일 발송 제한을 확인하고 별도 SMTP를 설정합니다. 비밀 키나 service_role 키는 사용하지 않습니다.

`/login`, `/signup`, `/forgot-password`, `/update-password`에서 인증 화면을 확인할 수 있습니다. 회원가입 후 이메일 링크로 인증하고, 비밀번호 변경 후에는 현재 세션을 종료해 새 비밀번호로 로그인합니다. 만료되거나 잘못된 링크는 오류 안내와 함께 로그인 화면으로 돌아갑니다.

근무표는 Supabase DB에 계정별로 저장합니다. 계정당 매장은 하나이며 첫 저장 시 기본 매장을 생성합니다. 결제·일회성 구매 권한과 다중 사용자 공동 편집 기능은 포함하지 않습니다.

## 사용 흐름

1. 오른쪽 근무자 목록의 `+` 버튼으로 직원 이름과 고유 색상을 등록합니다.
2. 왼쪽에서 `새로운 근무 타입 추가`로 해당 월의 타입을 만들거나 `이전 월 근무타입 복사하기`로 직전 월의 활성 타입을 가져옵니다. 조회만으로 자동 복사하지 않으며, 같은 이름은 건너뛰어 기존 타입과 배정을 보존합니다.
3. 오른쪽에서 현재 월의 기준 휴무 횟수를 입력합니다.
4. 날짜 위에 마우스를 올리면 나타나는 `+` 버튼을 눌러 직원과 일정 종류를 선택합니다. 근무를 선택하면 근무 타입도 지정합니다.
5. 캘린더의 이름표를 눌러 기존 배정을 수정합니다. 오른쪽 직원 이름을 누르면 해당 직원의 일정이 강조됩니다.
6. 직원별 휴무 횟수를 확인하고, 기준과 다른 항목을 조정합니다. 편집 폼의 적용 버튼은 화면만 변경합니다. PDF 버튼 왼쪽의 저장 버튼을 눌러 직원·근무 타입·휴무 기준·일정 변경을 DB에 반영합니다.
7. 미저장 상태에서 월 이동·로그아웃을 하면 저장 후 이동 / 저장하지 않고 이동 / 계속 작성을 선택합니다. 새로고침·탭 닫기에는 브라우저 기본 이탈 경고가 표시됩니다.

## 데이터 저장과 현재 범위

근무표는 **Supabase PostgreSQL**에 저장합니다. 자동 저장이나 브라우저 저장소를 사용하지 않습니다. 기존 임시 localStorage 데이터는 읽거나 이관하지 않으며 별도로 삭제하지도 않습니다.

| 테이블 | 저장 내용 |
| --- | --- |
| stores | 계정당 하나의 매장과 저장 버전 |
| employees | 모든 월에 공통인 근무자 명단 |
| schedule_months | 월별 휴무 기준 |
| shift_types | 월별 근무 타입과 삭제 표시 |
| assignments | 직원별 날짜 일정과 기타 메모 |

- 모든 업무 테이블에 RLS를 적용해 소유한 매장의 데이터만 읽고 수정합니다. 익명 접근을 차단하며 다른 매장 직원·다른 월 타입의 잘못된 연결도 DB에서 거부합니다.
- 첫 화면 조회 때 계정의 근무표를 읽습니다. 편집·월 이동 자체는 저장 요청을 보내지 않으며 저장 버튼으로 변경한 행과 삭제 목록만 하나의 RPC에 전송합니다.
- 전체 변경을 하나의 트랜잭션으로 처리합니다. 일부만 저장하지 않으며 오류가 나면 화면의 작성 내용은 유지합니다.
- 저장 버전이 달라지면 오래된 화면의 덮어쓰기를 차단합니다. 충돌 시 작성 내용을 확인한 뒤 명시적으로 취소하고 최신 근무표를 다시 불러올 수 있습니다.
- 저장 중 추가로 편집한 내용은 미저장 상태로 유지합니다. 저장하지 않고 이동하면 전역 직원 변경을 포함한 모든 미저장 내용을 마지막 저장본으로 되돌립니다.
- 새로고침·탭 닫기 경고는 브라우저가 지원하는 범위에서 동작합니다. 브라우저 강제 종료나 기기 전원 종료까지 작성 내용 보존을 보장하지 않습니다.
- DB 저장은 현재 작업 내용을 반영하는 기능입니다. 월별 버전 보관·과거 확정본 조회·PDF 파일 보관함은 포함하지 않습니다.
- PDF는 현재 화면의 미저장 편집 내용도 포함합니다. PDF 다운로드가 DB 저장을 대신하지 않습니다.

스키마와 DB 검증 절차는 [supabase/README.md](supabase/README.md)를 참고합니다.

### 공휴일 데이터

[한국천문연구원 특일 정보](https://www.data.go.kr/data/15012690/openapi.do)를 배포하는 [korean-holidays 공개 미러](https://github.com/raki-1203/korean-holidays)의 연도별 JSON을 브라우저에서 조회합니다. 외부 조회에 직원이나 근무표 데이터를 보내지 않습니다.

- 기본 데이터: 2026-11-04에 조회한 2025~2027년 공휴일
- 최신 데이터: 조회 성공 시 연도별로 메모리에 24시간 캐시
- 조회 실패: 기존 조회 결과 또는 기본 데이터를 유지하고 재시도 안내 표시
- 미제공 연도: 안내를 표시하며 공휴일 날짜를 임의로 계산하지 않음

새로 지정되는 임시공휴일 등은 미러 데이터 갱신 이후 다음 조회에 반영됩니다.

## 기술 구성

| 구분 | 사용 기술 |
| --- | --- |
| 프레임워크 | Next.js 16.4.3 · App Router · Turbopack |
| UI | React 19.3.0 · TypeScript · React Icons |
| 스타일 | Tailwind CSS 4 · DDS 디자인 토큰 및 공용 컴포넌트 |
| 상태 관리 | Zustand 5 · 편집 폼의 React reducer |
| 인증 | Supabase Auth · @supabase/ssr · 쿠키 기반 서버 인증 |
| 근무표 저장 | Supabase PostgreSQL · RLS · 트랜잭션 RPC |
| 검사 | ESLint 9 · TypeScript · Node.js 테스트 러너 및 tsx |

정확한 의존성 버전은 `package.json`과 `package-lock.json`에서 확인할 수 있습니다.

```text
app/                         페이지 배치, 메타데이터, 전역 스타일

  use-month-schedule.ts       월간 날짜 배치·직원·근무 타입·횟수 집계

lib/

  schedule-commands.ts        등록·수정·삭제 규칙과 예시 근무표 생성

  editor.ts                  편집 타입·폼 reducer·삭제 조건
  holidays.ts                공휴일 파싱과 기본 데이터 연결
  korean-holidays.json        기본 공휴일 데이터
providers/                   화면별 Zustand 스토어 제공
stores/                      편집·수동 저장·이동 확인·공휴일 캐시
supabase/                    테이블·RLS·저장 함수·검증 SQL
styles/                      DDS 디자인 토큰
scripts/                     개발 런타임·복사본 검사·테스트
```

캘린더 배치와 직원별 집계는 별도 훅으로 분리합니다. 날짜 셀은 해당 날짜의 배정을 구독하고, 직원 카드는 자신의 선택 여부를 구독합니다. DB 저장은 상단 저장 버튼에서만 수행하며 편집과 분리합니다.

## 개발 변경 사항 반영

현재는 `main` 브랜치에서 직접 작업합니다. 별도 작업 브랜치, 자동 PR 생성, PR 검토·머지 단계는 사용하지 않습니다.

1. `main`에서 기능이나 문서를 수정합니다.
2. 변경 범위에 맞는 검사를 실행하고 수정 내용을 확인합니다.
3. 프로젝트 소유자가 필요한 파일만 선택해 커밋합니다.
4. 프로젝트 소유자가 `main`을 원격 저장소에 직접 push합니다.

에이전트는 기본적으로 로컬 수정과 검사까지만 수행합니다. 별도로 요청하지 않으면 브랜치 생성, 커밋, push 또는 PR 등록을 실행하지 않습니다. 로컬 파일 감시와 시간 기반 PR 자동화도 사용하지 않습니다.

## PDF 출력 구현

현재 보고 있는 월의 전체 직원을 출력하며, 화면의 직원 검색·선택 강조 상태는 PDF에 적용하지 않습니다. PDF 생성은 브라우저에서 수행하고 근무표 데이터를 서버나 외부 서비스에 보내지 않습니다. 생성 엔진은 버튼을 누를 때 불러옵니다.

- `lib/schedule-pdf-data.ts`: 출력할 월의 직원·집계·범례·날짜 데이터 구성
- `components/pdf/schedule-pdf.tsx`: 근무 타입 → 근무 외 일정 → 캘린더 → 근무자 명단 배치
- `components/pdf/schedule-pdf-styles.ts`: 출력 전용 크기·간격·색상
- `components/planner/pdf-export-button.tsx`: 상단 오른쪽 버튼과 생성 상태
- `lib/download-schedule-pdf.tsx`: PDF Blob 생성 및 다운로드

PDF에는 `public/fonts`의 나눔고딕을 포함합니다. 글꼴은 Google Fonts 배포본을 사용하며 [SIL Open Font License](public/fonts/OFL.txt)를 함께 제공합니다. 화면 UI는 Tailwind를 유지하고, PDF만 React PDF의 전용 스타일을 사용합니다.

PDF 달력은 월 전체가 페이지 중간에서 나뉘지 않도록 배치합니다. 직원이 5명을 넘으면 최대 5명씩 나눈 월간 달력을 각각 새 페이지에 출력하고, 마지막에 전체 직원 명단과 집계를 표시합니다. 근무자 수와 월 기준 휴무일은 명단 제목 아래에서 확인할 수 있습니다.

### 미배정 기본 상태와 기존 데이터 호환

근무자 명단은 전역으로 관리하며 캘린더·PDF는 각 근무자의 시작일부터 표시합니다. 일정이 없는 날짜와 신규 월은 미배정으로 시작합니다. 휴무와 미배정을 명시적으로 저장하고 각각 집계합니다. 미배정 상태에서도 직원 이름은 표시합니다.

앱 내부 일정 모델은 버전 3을 유지하지만 DB에는 업무별 테이블로 나누어 저장합니다. 구버전 데이터 검증 함수는 호환성 검사에 남겨두며 브라우저 데이터 자동 이관에는 사용하지 않습니다.

### 월별 근무 타입

근무 타입은 `typesByMonth`에 월별로 저장합니다. 이전 월 복사는 새 ID로 타입만 추가하며 근무 배정은 복사하지 않습니다. 같은 이름의 활성 타입이 있으면 현재 월의 설정을 유지하고, 반복 복사로 중복 생성하지 않습니다. 직전 월에 활성 타입이 없으면 복사 버튼을 비활성화하고 안내합니다. 타입 복사도 실행 취소할 수 있습니다.

새 월은 빈 타입 목록으로 시작하며 사용자가 이전 월 타입을 복사하거나 직접 추가합니다.
